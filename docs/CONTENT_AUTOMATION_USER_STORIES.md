# AGI01 热点内容运营引擎 User Stories

## 1. 角色

| 角色 | 说明 |
|---|---|
| 内容运营 | 负责看热点、选题、生成文章、编辑平台稿 |
| 主编/审核人 | 负责事实、风险、风格和发布质量审核 |
| 管理员 | 负责来源、模型、skill、平台、任务配置 |
| 发布负责人 | 负责导出内容、发布、标记结果和回填数据 |
| 系统 Worker | 负责定时抓取、评分、生成、重试和状态推进 |
| 只读观察者 | 只能查看数据和内容，不能修改 |

## 2. Epic AI: 大模型配置

| ID | User Story | 验收标准 |
|---|---|---|
| AI-01 | 作为管理员，我要配置 DashScope provider，以便系统使用通义千问生成内容 | 支持 provider 名、base URL、默认模型、超时、启用状态 |
| AI-02 | 作为管理员，我要测试模型连接，以确认 API Key 和模型可用 | 测试返回成功、模型名、耗时；失败返回稳定错误 |
| AI-03 | 作为管理员，我要隐藏 API Key，以避免密钥泄露 | 前端只显示脱敏值，日志和错误响应不包含 key |
| AI-04 | 作为管理员，我要为不同任务配置不同模型 | 评分、研究、写作、翻译、改写、质量检查可独立配置 |
| AI-05 | 作为系统，我要记录每次模型调用 | 保存 provider、model、prompt_version、token、耗时、状态、错误 |
| AI-06 | 作为系统，我要处理模型失败 | key 无效、模型不存在、限流、超时、空响应都有稳定错误 |
| AI-07 | 作为管理员，我要设置每日调用预算 | 达到预算后自动任务暂停，手动任务需要确认 |
| AI-08 | 作为运营，我要看到模型不可用提示 | 页面明确说明不可用原因和下一步处理 |
| AI-09 | 作为系统，我要支持 fallback | DashScope 不可用时可退回规则评分或其他 provider |
| AI-10 | 作为管理员，我要禁用 AI 能力 | 禁用后抓取和人工编辑仍可用，生成按钮置灰 |

## 13. 关键异常场景

| 场景 | 期望行为 |
|---|---|
| DashScope key 无效 | 模型测试失败，自动生成暂停，热点抓取不受影响 |
| DashScope 模型不存在 | 返回模型配置错误，引导管理员修改 profile |
| 模型限流 | job 标记 retryable，按退避策略重试 |
| 模型输出空内容 | 保存运行记录，提示重新生成 |
| 模型输出非 JSON | 保存原始输出，重试一次，仍失败则进入人工处理 |
| 来源页面结构变化 | 保存 raw payload 和 last_error，来源状态变 error |
| 来源超时 | 当前 fetch run 失败，其他来源继续 |
| 热点重复 | 合并或忽略，不生成重复候选 |
| 热点误拒绝 | 管理员或运营可从 rejected 恢复 |
| 文章太长超 token | 自动分阶段生成，或提示拆分 |
| research brief 缺引用 | 不能进入正文生成，除非人工确认 |
| 人工编辑时 AI 任务完成 | AI 结果生成新版本，不覆盖人工编辑 |
| skill 仓库不可用 | 使用上一版快照继续工作 |
| 平台稿超长 | 平台页提示超出限制，并提供压缩重写 |
| 平台不支持外链 | 导出前提示删除或改写外链 |
| 未审核内容进入发布 | 系统拦截 |
| 发布失败 | 记录失败原因，可重试或退回修改 |
| 数据库或 worker 重启 | job 可恢复，不丢状态 |
| Kest flow 失败 | 对应功能不能算完成，必须修复或说明阻塞 |

## 15. Definition of Done

一个 user story 完成必须满足：

- API 和 Web 契约清楚。
- 数据模型或 migration 已更新。
- 成功路径和至少一个失败路径有测试。
- API 改动有 Kest flow。
- UI 改动在浏览器打开验证。
- 关键状态和错误可在界面看到。
- 不泄露密钥和敏感数据。
- 文档或 user story 状态同步更新。
- 单独 commit，commit message 能说明功能。
